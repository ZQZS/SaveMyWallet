# 桌宠开发指南

桌宠的目的是在用户主动打开时陪伴记账，并用轻量动作提示用户关注结余或待还金额。本次提交提供图包、类型和动作回退函数，供后续展示层联调。应用内角色、Windows 桌面窗口和提醒调度均为后续里程碑。

## 图包与动作

每只角色使用一个 `resources/pets/<id>/` 目录。图包清单定义稳定的 `id`、显示名、素材来源和各状态的图像路径。`version` 表示清单格式版本。示例的两张透明 SVG 为项目内绘制的开发占位素材。[清单类型与解析函数](../src/features/pets/manifest.ts) · [钱包猫示例](../resources/pets/wallet-cat/manifest.json)

| 状态 | 建议触发时机 | 资源 |
| --- | --- | --- |
| `idle` 待机 | 打开角色、关闭提示、一次交互结束 | 每个图包都提供 |
| `greet` 招呼 | 用户点按角色 | 可选，缺省时显示待机图 |
| `remind` 提醒 | 本地提醒已触发，需要向用户呈现 | 可选，缺省时显示待机图，提醒文字仍可显示 |

展示层取得清单后调用 `assetForState(manifest, 'remind')`。钱包猫返回 `art/idle.svg`，路径以该清单所在目录为基准。将来接入 Vite 时可用静态资源导入获得构建后的 URL，再交给图片组件。当前图包位于源码资源目录，客户端启动入口尚未导入。

同一动作可先用透明静态图联调，再换成动图并验证目标 WebView 的播放效果。若需要逐帧控制时长、循环或点击区域，可以在下一版清单中增加帧信息，同时保留版本 1 图包的加载路径。

## 添加第二只角色

1. 复制示例目录，为新目录和清单的 `id` 填入同一个唯一标识。写入用户可读的 `displayName`。
2. 在图包内放入待机图，可补充招呼图和提醒图。路径使用相对于清单的正斜杠写法，如 `art/idle.webp`。填写 `artworkSource`，第三方素材的作者、来源和许可记录可随图包保存。
3. 运行 `node --experimental-strip-types --test tests/pets.test.mjs`。测试会检查工作区内的每个图包、动作引用和缺省回退。展示层接入后，在目标设备核对透明背景、动作切换，以及关闭角色后的页面布局。

## 后续接入顺序

1. **先在应用内显示。** 在 `src/features/pets/` 增加角色组件与选择器，使用同一套图包和动作名。Windows 和安卓共用开关、点按打招呼、关闭角色和减少动画的行为。
2. **接入月度提醒。** 由账本的月度汇总提供目标月份、结余和警告线，本地规则先判断是否需要提醒，再由桌宠呈现。用户关闭提醒或切回普通记账时回到待机。后续 AI 可以提供提示文案；离线时继续展示本地文案。还款勾选、账单保存等操作留在对应的账本页面。
3. **分平台扩展。** Windows 可以新增用户手动开启的桌面窗口，分别验收置顶、拖动、退出和应用重启。安卓先验收应用内角色与页面前后台切换；若以后需要系统通知或跨应用悬浮窗，单独设计触发方式、系统权限和关闭流程。当前图包与动作接口本身不依赖这些能力。
