# SaveMyWallet 开发路线

用户打开账本时，最关心这个月还有哪些平台要还、下个月要准备多少钱，以及还完后工资能剩多少。桌宠可以为这些提醒提供一个可选入口。AI 可以解释本地汇总、协助读图，减少手工录入。

## 建议的实施顺序

月度解释和截图识别已接入 DeepSeek，分期试算可在月度账本中使用。M2、M3 的剩余工作聚焦真实 API 和设备验收。M4 仍规划通用问答与桌宠互动。

| 里程碑 | 目的与交付范围 | 依赖 | 验收场景 |
| --- | --- | --- | --- |
| M1 · 应用内桌宠 | 在月度账本中呈现可开关的角色，先打通静止、点击反馈和提醒表现 | 桌宠资源契约；无需 AI 服务 | Windows 和安卓均可显示同一素材包；可选动作缺失时回到待机；关闭宠物后仍可完整操作账本 |
| M2 · 自带密钥与 AI 提醒 | 设置、检测、替换和删除每台设备的 DeepSeek API Key，主动请求所选月份的解释 | 原生凭据存储与本地月度汇总 | 在设备上验证有效密钥、密钥撤销、超时和断网，核对界面中的预计结余和警告线。 |
| M3 · 识图辅助录入 | 用户先预览截图，再发送给 DeepSeek，逐笔核对草稿并确认入账 | M2 的凭据与本地账单表单 | 合成截图覆盖分期和多笔款项。补全缺失月份，核对每期金额。结束审核后，账本中只有已确认的款项。 |
| M4 · AI 互动 | 通过账本或宠物入口提问，例如「下个月还完会剩多少」；用户决定本次可使用的上下文 | M2；从宠物发起时依赖 M1 | 同一月份的回答可与账本核对；互动过程中不会改变还款状态；取消请求或服务不可用时可继续记账 |
| M5 · Windows 桌面陪伴 | 将应用内已验证的角色放进可关闭的独立桌面窗口；继续复用资源包和互动逻辑 | M1；接入 AI 对话时再依赖 M4 | 验证主窗和宠物窗同时打开、移动到另一显示器、关闭及重新打开；安卓沿用应用内入口，单独验证触控和返回操作 |

## 后续候选

- **平台数据采集。** 目标是减少重复录入。选定具体数据源后实现采集器，把来源与外部记录编号交给草稿审核，用重复采集样例验证去重。
- **WASM 模板性能验证。** 评估新实现时，在 Windows 和 Android 上用同一份合成大账本测量首次加载和连续切月的耗时。
- **系统定时提醒与小游戏。** 定时通知需要补充提醒时间、授权和重复通知处理。小游戏可以复用宠物素材，待基本的提醒与互动验证后再确定玩法。

## 开始下一阶段前

桌宠的首个决策是角色与素材授权。AI 接入使用 `deepseek-flash`。收集脱敏或合成的账单样本，分别记录总额和每期金额的识别结果，以及信息缺失时是否留空。进入验收时记录实际测试的平台、设备和样本。

具体接口与资源示例见[桌宠开发说明](pets.md)、[AI 功能开发说明](ai-features.md)及[已有扩展接口说明](extensions.md)。
