# 开发计划

当前优先维护 Windows 和安卓的离线账本同步。在 Android 真机回归中同时覆盖同步和手动备份迁移，再推进 M1 应用内桌宠。M2 的供应商选择与凭据设计可以并行。已交付范围及各阶段的完成条件见[开发里程碑](milestones.md)。

## 近期工作

| 工作项 | 实施步骤 | 完成时可检查的结果 |
| --- | --- | --- |
| 双端离线同步验收 | 从同一云端基线出发，两端断网确认同一笔补款，再分别联网。另一组用例在服务器接收 12 期分期后丢弃响应，重发原操作。 | 补款可手动选择本机或云端金额和月份，双方最终保留同一条明细。分期重试后仍为 12 条。[同步协议](../backend/docs/sync.md) |
| 双端账本回归 | 在 Windows 和 Android 真机使用独立测试账本，录入自定义平台、跨年分期和预计补款。结清平台后补录一笔，再用 JSON 将账本迁移到另一台设备。 | 两端各月金额和已还状态一致。后来补录的明细仍待还。取消导入后原账本完整。记录测试设备、应用版本和结果。 |
| M1 应用内桌宠 | 选定可随包分发的角色素材，从现有资源清单接入待机和点击动作。在设置中接入开关，再让角色显示已有的本地预警。 | Windows 可用鼠标点击，Android 可用触控。关闭角色后可以继续记账，缺少某个动作时能显示待机图。[桌宠开发说明](../frontend/docs/pets.md) |
| M2 AI 提醒 | 确定首个供应商和所需模型能力。在原生层实现凭据保存、替换和删除，再接入用户主动触发的按月提醒。 | 用合成账本核对文案中的金额。密钥失效或断网时仍能看到本地预警，导出的账本不含密钥。[AI 接入说明](../frontend/docs/ai-features.md) |

## 后续功能与依赖

- **M3 识图录入**依赖 M2 的凭据和支持图像的模型。先接入选图、预览和取消，再将识别结果映射为可编辑草稿。用一张含多笔账单的合成图验证平台、还款月份和每期金额，确认所选草稿后才写入。
- **M4 AI 互动**复用 M2。从账本入口提供用户选定月份的汇总，从宠物发起互动时再接入 M1。用“下个月还完剩多少”核对回复中的金额，并验证取消请求后能继续使用清单。
- **M5 Windows 桌面陪伴**在 M1 的角色和状态稳定后再独立开窗，验证窗口移动、关闭、重开与主账本的关系。安卓继续使用应用内角色。

## 跨模块候选工作

| 方向 | 启动条件与首步 | 验证场景 |
| --- | --- | --- |
| WASM 模板双端性能验证 | 如需评估新的计算实现，可在 Windows 与 Android 上用同一份合成大账本运行模板与 TypeScript 汇总。 | 核对金额与平台明细，分别记录首次加载、数据转换与重复切换月份的耗时。[模板入口](../wasm-lib/README.md) |
| 平台数据采集 | 选定具体数据源及可用的导出或授权读取方式。将记录转换为带来源和外部账单编号的草稿，交由用户核对。 | 同一批记录重复导入时可识别重复项。平台无法匹配或分期金额不明确时可手工补全。[采集契约](../frontend/docs/extensions.md#数据采集脚本) |

系统定时通知与小游戏保留为产品候选。是否启动、预期用户操作及平台差异，可在相应功能进入排期时记录。[客户端路线图](../frontend/docs/roadmap.md)
