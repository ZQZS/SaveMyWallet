# SaveMyWallet 开发里程碑

## 已交付

| 版本或阶段 | 用户或开发者获得的能力 | 核对方式 |
| --- | --- | --- |
| 0.1.0 · 首版 | Windows 和安卓有可安装的本地账本客户端。 | 本地 `frontend/release/` 留存同版本的 Windows x64 安装包和 Android arm64 调试 APK。 |
| 0.1.1 · 月度账本与模块化 | 用户可新增平台，录入单次、分期与预计补款，按月勾选还款并查看结余预警。页面按菜单和功能拆分。 | 同月同平台的多笔账单合为一组。勾选只结清组内已确认的待还明细，整月应还与预计结余保持原值。 |
| 0.2.0 · 设置与账本维护 | 用户可切换中英文，通过 JSON 备份在设备间手动迁移账本，并在输入 `重置` 后清空账本。 | 在另一份测试账本预览并确认导入，逐笔核对还款状态和每期金额。重置后检查初始平台、工资与警告线。 |
| 工程整理 · 沿用 0.2.0 | 客户端集中在 `frontend/`，一键脚本可以构建双端安装包。 | 在 Windows 从仓库根目录运行 `.\frontend\build.cmd`，前端测试通过后可在 `frontend/release/` 找到两个平台对应版本的安装包。 |
| 0.3.0 · 离线同步 | Windows 和安卓可绑定同一 PostgreSQL 账本，从同步页处理同笔补款的不同金额或月份。 | 断开网络确认同一补款并分别重连，手动选择后两端金额一致。上传 12 期分期后丢弃回执，重发后仍为 12 条。[同步协议](../backend/docs/sync.md) |
| 月度汇总与 WASM 模板 | 前端使用 TypeScript 计算当月、下月和预算预览，另提供可独立构建的 .NET WebAssembly 示例。 | 在 `frontend/` 运行 `npm test` 验证前端汇总，运行 `npm run test:wasm` 可对照模板结果。[模板说明](../wasm-lib/README.md) |

0.3.0 的同步验收使用独立测试账本和 PostgreSQL 17。Windows 桌面客户端分别核对了「采用本机修改」和「采用云端结果」。Android 9 模拟器断网新增 12 期分期并强制结束应用，重开、联网后云端只有 12 条。对同一笔补款选择次年 1 月 350 元后，Windows 和安卓保留相同的明细 ID、月份和金额。反向验证中，Windows 新增的 2 月 26.15 元也以原 ID 出现在安卓账本。

安卓覆盖安装还验证了早期 v2 同步库到 v3 的迁移。升级前离线录入的两期保留原 ID，升级后沿用原绑定上传，每期各入账一次。安卓实体设备验收仍待补充。[双副本回归命令](../backend/README.md#接口和验证) · [客户端构建说明](../frontend/README.md#一键构建)

## 已规划的客户端里程碑

M1 和 M2 可以并行。当前已有桌宠样包与 AI 能力契约，设置页也预留了入口。下表以用户实际能在客户端完成的操作作为交付标准。

| 里程碑 | 开始条件 | 验收场景 |
| --- | --- | --- |
| M1 · 应用内桌宠 | 确认首个角色素材及其授权。 | 在 Windows 和安卓启用同一角色，点击时有反馈，缺少可选动作时回到待机。关闭角色后可继续操作月度清单。 |
| M2 · 用户密钥与 AI 提醒 | 确定首个供应商和原生凭据存储方案，沿用本地月度汇总。 | 用户可设置、替换、删除密钥。主动请求提醒时，文案中的金额可与所选月份核对。离线时仍可查看本地预警。 |
| M3 · 识图辅助录入 | M2 的凭据链路可用，所选模型支持图像输入。 | 用一张含多笔消费的合成截图生成草稿，逐条修正平台、月份与每期金额。保存后只出现勾选的记录，取消时账本维持原值。 |
| M4 · AI 互动 | 依赖 M2。从宠物发起互动时还依赖 M1。 | 用户选择本次可使用的账本信息，询问下月结余。回答的金额可对照本地汇总，原有还款勾选状态维持原值。 |
| M5 · Windows 桌面陪伴 | 依赖 M1。加入 AI 对话时还依赖 M4。 | Windows 可移动、关闭及重新打开独立宠物窗口，主账本仍可操作。安卓继续通过应用内入口互动。 |

服务端部署、双端回归和其他候选功能的安排见[后端开发说明](../backend/README.md)和[近期开发计划](development-plan.md)。
